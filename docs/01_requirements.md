## このゲームは何か

**じゃんけんを1回出すだけで戦う、一本道のRPG。**

グリコ（じゃんけん階段）の「**勝ち方によって得られるものが違う**」という非対称が中核。
グーは溜めて爆発する手、チョキは安定した高火力、パーは削られてから効く手であり、
**自分のHPと「にらみ」の値によって、最良の手が戦闘中に入れ替わる。**

敵を1体ずつ倒して階段を上がっていき、5体目を倒せばクリア。

## やること（MUST）

### 戦闘

- ADR 0001 のルールを実装する（グー/チョキ/パー・にらみ・上限2・あいこダメージ）
- 敵の手は**重み付き抽選**で決める。乱数は**ここ1箇所のみ**（`src/lib/rng.ts` 経由）
- プレイヤーHP は **25**。敵HP は敵ごとに **18〜26**（`/balance` で動かす出発点）
- **敵の既定の値表はプレイヤーと同じ**（グー3+にらみ×4 / チョキ5 / パー3ダメージ+3回復）。
  **ただし敵ごとに別の値表を持たせてよい**（`docs/adr/0004-enemy-hand-table.md`）。
  **敵は強化されない。** 敵の個性は偏り・耐性・HP・あいこルール・**本気の強化**・**値表**で出す
- **値表を変えた敵は、標準と違うところを画面に出す。**
  被弾の数字は自動で実値になるが、**回復量とにらみ倍率は画面に出ていない**ので、
  そのままでは読めないまま変わる（「画面に出る数字は必ず実値」に反する）。
  文言は手書きせず、`BASE_HANDS` との差分から組み立てる
- **敵もパーで回復する。** にらみは共有なので、敵のグーにもにらみ×4 が乗る
- 耐性の倍率は**基礎ダメージにのみ**掛かる。にらみの加算と、パーの回復には掛からない
- 回復は最大HPを超えない。超過分は捨てる
- **回復量は「そのターンに与えたダメージ − 1」を超えない。**
  強化前のパー（3ダメージ+回復3）では `min(3, 2)` で **回復は 2 に抑えられる**。
  **耐性でダメージが下がったときに回復が上回ると、HP総和が増えて戦闘が終わらなくなる。**
  例: パーに耐性 0.5 の敵ならダメージ1・回復0 に抑えられる。
  （設計時に見つかった穴。`docs/03_detailed-design.md` 節4）

### 連打の罰（`docs/adr/0003-repetition-window.md`）

**同じ手ばかり出すと威力が下がる。散らして出せば下がらない。**

- **直近4手（今回の手を含む）で、その手を3回以上出していたら弱化する**
  - 弱化量 = `min(3, max(0, その手の回数 − 2))`。ダメージからこの値を引く
- **均等に回しても、2連続を挟んでも罰は付かない。** 3連続から付く
- 弱化しても**ダメージは最低 1 で止まる**
- 履歴は**陣営ごと**に持つ（プレイヤーと敵で別々）
- **戦闘が始まるたびに履歴は空に戻る**
- **ルールは敵にも同じように適用する。** 敵の手の抽選は重み付きのままで、
  履歴は**敵の手の選び方には影響しない**（履歴に反応させない）
- **耐性・にらみとの関係**: **弱化を基礎ダメージから先に引き、そのあとに耐性を掛ける。**
  順序を逆にするとバランスの実測値と合わなくなる。
  **にらみの加算と回復量には効かせない**（耐性と同じ扱い）

> **2026-08-10 に方式を変えた。** ADR 0002 は「熱」（使うと溜まり、毎ターン冷める）で
> 実装していたが、**手が3種類しかないため溜まる速さが冷める速さを上回り、
> 均等に回しても全部の手が弱っていく**状態になっていた。
> 罰していたのが「連打」ではなく「使うこと」だったので、条件を書き直した。

```
実効ダメージ = max(1, floor(max(1, 基礎ダメージ − 弱化量) × 耐性)) + にらみ × stareBonus
```

**連打の判定に乱数は使わない。** 乱数は敵の手決定の1箇所のまま。

### 1ターンの処理順序

**順序が結果を変える箇所があるので、ここで固定する。**

1. プレイヤーが手を選ぶ
2. 敵の手を抽選する。**このときプレイヤーの手を参照しない**（後出しの禁止）
3. 勝敗を判定する
4. **あいこのとき**
   - にらみが上限（2）未満 → にらみ +1。**HPは動かない**。ターン終了
   - にらみが上限 → **双方に1ダメージを同時に適用**。にらみは上限のまま
5. **決着したとき** — 勝者の手の効果を適用し、**にらみを 0 に戻す**
   - ダメージは相手のHPへ、回復は自分のHPへ。**両者は独立なので順序は問わない**
   - 回復は自分の最大HPで頭打ち
6. 決着判定
   - **双方が0以下 → プレイヤーの敗北**（引き分けは作らない）
   - 片方だけ0以下 → その側の敗北
   - HPは0未満にしない（0で止める）

### 敵は5体、順番に強くなる

`docs/00_research.md` 節9.5 の導入順に従う。**3軸を同時に投入しない。**

| # | 変える軸 | ねらい |
| --- | --- | --- |
| 1 | なし（標準・耐性なし） | ルールを覚えさせる。**あいこ→にらみ→グーで大きく勝つ**を体験させる |
| 2 | 手の偏り（グー偏重） | チョキが刺さらない敵 |
| 3 | 手の偏り（チョキ偏重） | 回復させてくれない敵 |
| 4 | 偏り＋耐性1つ | 均衡そのものが変わる敵 |
| 5（ボス） | 偏り＋耐性＋あいこルール変更 | 総合 |

- **敵ごとの手の偏りは画面に明示する。** 読み合いの材料は公開情報にする
- **敵ごとのあいこルールは2種類だけ**にする。**1〜4体目は標準、5体目（ボス）だけ「にらみ+2」。**
  （調査の節9.5 は3種類挙げていたが、「あいこで双方1ダメージ」は
  にらみ上限到達時の共通ルールとして全敵にすでに効いているため、敵固有ルールからは外す）

### 成長（最小形）

- 敵を1体倒すごとに、**グー / チョキ / パー のどれか1つを +1** する（3択から選ぶ）。
  **強化のチャンスは4回**（1〜4体目を倒したとき）。5体目を倒すとその場でクリアなので強化はない
- **強化の行き先は手ごとに違う**（`docs/adr/0003-repetition-window.md`）

  | 手 | 強化1回につき |
  | --- | --- |
  | グー | **にらみ倍率 +1**（×4 → ×5 → ×6） |
  | チョキ | ダメージ +1 |
  | パー | ダメージ +1 |

- **回復側には絶対に乗せない。** パーを強化しても `heal` は 3 のまま
  （回復側に乗せると、パー勝ちでHP総和が減るという終了保証が壊れる）。
  ただし**打点が上がると「与ダメージ − 1」の頭打ちが緩む**ので、
  **パーを1回強化して初めて回復3が出せる**ようになる（打点3のときの回復は2）
- **にらみ倍率に乗せてよい理由**: にらみの加算は純粋な追加ダメージで、
  回復にも耐性にも関わらない。上の終了保証の理由が当たらない
- **同じ手は2回まで。** 上限に達した手は**押せない状態で表示する**（消さない。現在値は見せる）
  （4回の強化を1つの手に集中させると、その手一択に戻るため）
- 経験値・レベルという概念は作らない
- **ゲームオーバーになったら強化はすべてリセットされる。** タイトルに戻ると最初から

### 敵のCPU

- **全ての手に最低 10% の確率**を持たせる（読み切られない・読み外しの余地を残す）
- **プレイヤーの手の履歴には反応しない**
- 分布を変えるのは**2フェーズだけ**。切り替えの条件は
  **「敵自身のHPが最大HPの半分以下になったこと」の1つだけ**にする
- **本気（後半）フェーズでは、敵の全手のダメージに `desperateBonus` を足す**
  （`docs/adr/0003-repetition-window.md`）。手の傾向が変わるだけでは
  危険になった実感が薄いため。**切り替えの条件は増やさない**
- **同じターンにプレイヤーの入力を見てから手を決めない**（後出しの禁止）

### 画面

1. **タイトル** — 開始
2. **戦闘** — 敵、双方のHP、**にらみ**、**敵の3手の確率と威力**、じゃんけん3ボタン
3. **強化選択** — 3択
4. **結果** — クリア / ゲームオーバー

**「にらみ」は画面の目立つ場所に大きく出す。** ここが伝わらないと、
このゲームはただの運ゲーに見える（`docs/00_research.md` 節9.8）。

## 1プレイの流れ

```
起動
 → タイトル画面（「はじめる」）
 → 1体目の戦闘
      毎ターン: じゃんけん3ボタンから1つ選ぶ
                → 敵の手が出る → 勝敗と効果を表示 → HP と にらみ を更新
      どちらかのHPが0以下になるまで繰り返す
 → 勝ったら 強化選択画面（グー/チョキ/パー から1つ +1）
 → 2体目 … 5体目（ボス）
 → 5体目を倒したら 結果画面「クリア」
 → 途中で負けたら 結果画面「ゲームオーバー」
 → どちらもタイトルに戻れる
```

**1戦は 10〜14ターン**。実測は13.0ターン（`scripts/measure.ts`）。5戦で**10〜20分**の見込み。

## 画面一覧

| 画面 | 出るもの | 遷移先 |
| --- | --- | --- |
| タイトル | タイトル、はじめる | 戦闘（1体目） |
| 戦闘 | 敵、敵HP、自HP、**にらみ**、**敵の3手の確率と威力**、直前の手合わせ、じゃんけん3ボタン | 強化選択（勝ち） / 結果（負け） |
| 強化選択 | グー/チョキ/パーの現在値と3択（上限の手は押せない状態で表示） | 戦闘（次の敵） |
| 結果 | クリア または ゲームオーバー | タイトル |

**行き止まりを作らない。** 結果画面からは必ずタイトルに戻れる。

## 保存

**しない。** リロードすると最初からになる。
ゲームオーバーからタイトルに戻った場合も、強化・HP はすべて初期値に戻る。

## 未確定のまま残すもの

**バランスの数値は `/balance` で動かす。** 要件では出発点だけを決めている。

- 敵5体の具体的な偏り・耐性・HP（`src/data/enemies.ts`）
- 強化の +1 という刻み幅
- プレイヤーHP 25 という値
- 連打の罰の窓の広さ（`window`）と許す回数（`allowed`）
- 本気フェーズの強化量（`desperateBonus`）

**バランスの完璧さは3日の目標ではない**（`docs/10_workflow.md`）。遊べる状態を優先する。
