# テスト計画

> ステータス: **一部着手** — `lib/rng` のみ実装済み

## 3層の方針

| 層 | 置き場所 | 検証するもの | 自動化 |
| --- | --- | --- | --- |
| ユニット | `tests/unit/` | `domain/` の純粋関数、`lib/` | vitest |
| **シナリオ** | `tests/scenario/` | `domain` + `application` を通した戦闘1試合 | vitest |
| ブラウザ確認 | 手動 | UI を含めた画面遷移・表示・操作 | なし |

## 結合テストの範囲

**3日で作る規模なので、しっかりした結合テストは行わない。** そのぶん、
自動化できる範囲を `tests/scenario/` に寄せる。UI を含めない結合であれば
vitest で決定的に回せるため、コストがほぼかからない。

### `tests/scenario/` は3本まで

1. プレイヤーが勝つまでの1試合 — 決着時の状態
2. プレイヤーが負けるまでの1試合 — HP が負にならない、敗北状態になる
3. あいこが連続しても進行する — **無限ループにならない**（ターン上限で検出）

### バランス調整に耐えること

シナリオテストは**決着時の状態だけ**を検証する。途中の数値を検証すると、
`src/data/` の数値を変えるたびにテストが壊れ、バランス調整ができなくなる。

- 書く: 「決着したとき、勝者の HP が 1 以上」
- 書かない: 「3ターン目に HP が 12」

### ブラウザ確認は手動、回数を絞る

E2E フレームワークは導入しない（3日の規模に対して重い）。
次の3回だけ、開発サーバを起動して手で確認する。

1. 各画面が組み上がった時点
2. 全画面が繋がった時点
3. バランス調整の最終確認

## UI はユニットテストしない

`src/ui/` にテストは書かない。3日の規模ではコストが見合わないため、
ブラウザでの目視確認に任せる。そのぶん `domain` を厚く検証する。

## テスト済み

- `lib/rng` — 再現性、値域、`pick` の境界

## これから書く

設計は `docs/03_detailed-design.md`。**期待値の根拠は必ずそこに書かれているものを使う。**
自分で新しく仕様を決めない。

### `tests/unit/`

| ファイル | 検証するもの |
| --- | --- |
| `hand.test.ts` | `judge` の9通り。`judge(a,a)==='draw'`、勝敗の対称性 |
| `handTable.test.ts` | `canUpgrade` の上限、`applyUpgrade` が上限で据え置き、`buildHandTable` が **damage にだけ**加算し `heal` を動かさない |
| `enemy.test.ts` | `enemyPhase` の境界（`hp*2 === maxHp` は `desperate`）、`handProbabilities` の**和が1**と**全手 0.1 以上**、`decideEnemyHand` が `rng.next()` を**ちょうど1回**呼ぶ |
| `battle.test.ts` | 節4の不変条件1〜8と、具体例1〜5をそのまま |

**`battle.test.ts` が本体。** 特にこの3つは落とさない。

- **決着したターンで `playerHp + enemyHp` が必ず1以上減る**（終了保証）
- **耐性0.5のパーで回復がダメージを上回らない**（例3。ここが壊れると戦闘が終わらない）
- **同時に0以下ならプレイヤーの敗北**（例5。引き分けを作らない）

### `tests/scenario/`

`docs/04_test-plan.md` の方針どおり**3本まで**。`application/game.ts` を通す。
固定シードで回し、**決着時の状態だけ**を見る。途中の数値は見ない。

1. プレイヤーが勝つまでの1周 — 5体倒して `phase === 'result'` かつ `cleared === true`
2. プレイヤーが負ける1試合 — `cleared === false`、`playerHp === 0`、HPが負になっていない
3. **あいこが連続しても進行する** — ターン上限（例: 200）を置いて回し、
   **上限に達する前に必ず決着すること**。にらみが `STARE_MAX` を超えないこと

### 書かないもの

- `src/ui/` のテスト（方針どおり）
- `src/data/` の数値そのものを検証するテスト（`/balance` で壊れるため）
