# ADR 0002: 同じ手の連打を「熱」で罰する

- ステータス: **確定**
- 決定日: 2026-08-10
- 前提: `docs/adr/0001-battle-model.md`（**覆さない**）

## 背景

`/impl` が終わり遊べる状態になった時点で、実装済みの `domain` をそのまま回して
戦略ごとの勝率を測った（各6,000〜20,000戦）。**ADR 0001 が狙った性質が出ていなかった。**

ADR 0001 の採用理由はこう書かれている。

> 手の価値が局面（自分のHP・にらみ）で動くため、**3手すべてが「最良になる局面」を持ち、
> 最良手が戦闘中に入れ替わる。**

実測はこうだった。

| 指標 | 実測値 | 意味 |
| --- | --- | --- |
| 最適プレイ時の手の使用分布 | グー **10%** / チョキ 47% / パー 43% | **グーがほぼ死んでいる** |
| 最適プレイ vs 最良の機械パターン | **+0.0pt** | **考えても得しない** |
| 1戦の平均ターン数 | 8.1ターン | 要件の「10〜14ターン」に届いていない |

「最良の機械パターン」は、1手固定・2手交互（3通り）・3手循環のうち最も強いものを指す。
**状態を一切見ないプレイが、状態を見るプレイと同じ勝率だった。**

### なぜそうなったか

にらみ満タンのグーは `3 + 2×2 = 7` ダメージ。チョキは `6` ダメージ。
**あいこを2回耐えて溜め切った報酬が +1 ダメージしかない。**
溜まるまで不利な手を出し続けるコストに見合わないため、グーが選ばれない。

ADR 0001 は「**敵の手の分布を調整して均す**」を却下する際、
「中途半端に寄せても静的な最良手が1つ残るだけ」と書いていた。この予測が的中していた。
**偏りは個性としては機能するが、判断は生まない。**

## 決定

### 1. 手に「熱」を持たせる

**使った手は熱を持ち、しばらく威力が下がる。使わなければ冷める。**

```
熱は手ごと・陣営ごとに持つ（プレイヤーと敵で別々）。

弱化量 = min(HEAT_MAX_PENALTY, floor(熱 / HEAT_GAIN))
        ダメージからこの値を引く。ダメージは最低 1 で止まる

ターンの終わりに:
    全部の手の熱を 1 減らす（0 未満にはしない）
    そのターン出した手の熱に HEAT_GAIN を足す

HEAT_GAIN = 4、HEAT_MAX_PENALTY = 3
戦闘が始まるたびに熱は 0 に戻る
```

体感としては「**使った直後から -1、約4ターンかけて戻る。連打すると -2、-3 と深くなる**」。

**ルールは敵にも同じように適用する**（ADR 0001 の原則を維持）。
敵の手は重み付き抽選のままで、履歴には反応しない（要件「敵に履歴学習AIを作らない」を維持）。

### 2. 手の値を改定する

熱の導入で手の価値の計算が変わるため、あわせて数値を改定する。**構造は変えない。**

| 手 | ADR 0001 | 本ADR | 変更点 |
| --- | --- | --- | --- |
| グー | 3ダメージ ＋ にらみ×**2** | 3ダメージ ＋ にらみ×**3** | 溜めの報酬を上げる |
| チョキ | **6**ダメージ | **5**ダメージ | 一強を緩める |
| パー | 4ダメージ ＋ 3回復 | 4ダメージ ＋ 3回復 | **変更なし** |

**グー=溜めて爆発 / チョキ=高火力 / パー=削られてから効く、という非対称は完全に維持する。**
ADR 0001 の決定ブロックに数値が直接書かれているため、ここで改定を明記しておく。

### 3. `BattleState` は変えない

熱は `application` 層が持ち、毎ターン組み立てた `HandTable` を `ctx` で渡す。
`resolveTurn` は既に毎ターン `ctx.playerHands` を受け取る設計なので、
**`domain/battle.ts` と `BattleState` は1行も変わらない。**
ADR 0001 の「戦闘の状態に増えるのは `stare` の1フィールドだけ」はそのまま守られる。

## 効果（実測）

| 指標 | 現行 | 本ADR適用後 |
| --- | --- | --- |
| 手の使用分布 | グー 10% / チョキ 47% / パー 43% | **グー 24% / チョキ 35% / パー 40%** |
| 最適プレイ vs 最良の機械パターン | +0.0pt | **+17.0pt** |
| 1戦の平均ターン数 | 8.1 | **10.5**（要件の10〜14に収まる） |
| 通しクリア率（5戦＋強化4回） | 21.0% | **30.0%** |

**難易度を上げずに思考停止だけを罰している**点が採用の決め手。
最適プレイの勝率は 68.3% → 72.8% とほぼ横ばいで、
機械的パターンの勝率だけが 68.4% → 55.9% に落ちている。

### 数値の信頼度

**機械的パターンの勝率は、評価関数に依存しない実測値。**
**最適プレイ側は自作のEV貪欲法で打った参考値**であり、真の最適とは限らない。
したがって「+17.0pt 強くなる」ではなく、
「**機械的パターンが最適でなくなった**」ことの証拠として読むこと。

## 却下した案とその理由

後から蒸し返さないために残す。**いずれも実測または ADR 0001 との衝突で落ちている。**

| 却下した案 | 出典 | 理由 |
| --- | --- | --- |
| **累積型**（戦闘中の総使用回数で減衰） | FEの武器耐久度 | **効かない**（かかしで +0.1pt）。かつ戦闘が長引くほど全手が痩せ、ADR 0001 が却下した「カード制限型」と同じテンポ問題を持つ |
| **連続型**（同じ手を連続した回数で減衰） | — | **2手交互で素通りできる。** 1手固定は 24.8% に落ちるが2手交互が 60.8% で残り、優位は +6.0pt 止まり |
| **PP（技の使用回数上限）** | ポケモン | 手札切れの扱いが要る。ADR 0001 却下済みの「カード制限型」そのもの |
| **リキャスト（数ターン使えない）** | MMO全般 | **3択で1つ塞ぐと選択肢が2つになり、敵にも読まれて読み合いが壊れる** |
| **弱点を突くと追加行動** | ペルソナ、オクトパス | ADR 0001「行動はじゃんけんを1回出すことだけ」に抵触 |
| **溜めて解放するゲージ** | ブレイブリーデフォルト | **にらみが既に同型。** 重複する |
| **敵が受けた手に慣れる** | 女神転生系の耐性変化 | 敵ごとの個性にはできるが、要件「敵に履歴学習AIを作らない」とグレー。状態も増える。**将来の候補として残す** |
| **履歴キュー方式**（直近N手の出現数で減衰） | スマブラのワンパターン相殺 | **効果はほぼ同等**（+17.0pt vs 熱方式 +16.1pt）だが、直近6手のキューを両陣営ぶん持つ必要があり状態が大きい。**熱方式は同じ効果を `Record<Hand, number>` 2つで得られる** |

**採用した熱方式は、スマブラのワンパターン相殺／対戦格闘のコンボ補正と同じ系統**であり、
それを履歴キューなしで近似したもの。

## 影響

- `src/domain/handTable.ts` — 熱の型と純粋関数を追加（`applyHeat` / `advanceHeat`）
- `src/application/game.ts` — `GameState` に `playerHeat` / `enemyHeat` を追加。戦闘開始時に 0 に戻す
- `src/data/hands.ts` — グーの `stareBonus` 2→3、チョキの `damage` 6→5
- `src/ui/screens/battle.ts` — **弱化していることが見えるようにする**（数字は既に実ダメージ表示なので目印を足すだけ）
- `src/domain/battle.ts` / `BattleState` — **変更なし**
- 乱数の使用箇所は敵の手決定の1箇所のまま。**熱に乱数は使わない**

## 積み残し

- **1体目（かかし）での脱落が19〜26%と全5体で最も高い。** 強化0回で戦うため。
  `/balance` でHPの調整を検討する。本ADRとは独立
