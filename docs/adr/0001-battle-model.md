# ADR 0001: じゃんけんを戦闘にどう組み込むか

- ステータス: **確定**
- 決定日: 2026-08-09

## 背景

じゃんけんを中核に据えたRPGを作る。組み込み方によって `domain/` の構造と、
RPG としての伸びしろが決まるため、実装前に1案へ確定させる必要があった。

調査は `docs/00_research.md`（グリコ前提・本編）と
`docs/00b_research-battle.md`（戦闘へのダメージ変換・旧前提）にある。

## 決定

**グリコ（じゃんけん階段）の「勝ち方によって得られるものが違う」非対称を、戦闘に持ち込む。**
戦闘中のプレイヤーの行動は**じゃんけんを1回出すことだけ**。他の行動選択肢は作らない。

```
毎ターン、じゃんけんを1回する。勝った側だけ効果が出る。

  グー   3ダメージ ＋ にらみ×2
  チョキ 6ダメージ
  パー   4ダメージ ＋ 3回復

あいこで「にらみ」が1溜まる（上限2）。決着がついたら 0 に戻る。
にらみが上限のときのあいこは、双方が1ダメージ受ける。
にらみは両者で共有する。
```

**ルールは敵にも同じように適用される。** 敵も同じ値表を使い、パーで回復し、
共有のにらみがグーに乗る。**強化されるのはプレイヤーだけ**で、敵の個性は
手の偏り・耐性・HP・あいこルールで出す（`docs/01_requirements.md`）。

**採用理由**: 手の価値が局面（自分のHP・にらみ）で動くため、
**3手すべてが「最良になる局面」を持ち、最良手が戦闘中に入れ替わる。**
判断材料は両者に見える公開情報だけで、乱数は敵の手を決める1箇所しか要らない。
検算と根拠は `docs/00_research.md` 節8〜9。

## 却下した案とその理由

後から蒸し返さないために、なぜ選ばなかったかを残す。

### 戦闘の組み立て方

| 却下した案 | 理由 |
| --- | --- |
| **素のじゃんけん即時判定**（00b 案1） | 手を選ぶ理由が読み合いだけになる。量の非対称では最良手が固定される（節8.5 の証明） |
| **手固有スキル型に命中率を足す**（00b 案2） | 乱数系統が2つになり、じゃんけんの運＋命中の運で二重運ゲーになる |
| **カード制限型**（00b 案3） | 手札切れの扱いを別途決める必要があり、雑魚戦を繰り返すテンポと相性が悪い |
| **行動権争奪型**（00b 案4） | 1対1では先手後手が決着ターンでしか結果を変えない。**最も実装が重いのに、じゃんけんがほとんどのターンで無意味になる** |
| **形A（量だけの非対称）** | 均衡が戦況で動かず、1ターン目と10ターン目で読みの内容が変わらない |

### 「チョキが強すぎる」への対策

| 却下した案 | 理由 |
| --- | --- |
| **敵の手の分布を調整して均す** | 均衡（2:2:1）まで寄せると**プレイヤーの3手が全部 EV 0 になり、選択そのものが消える**。中途半端に寄せても静的な最良手が1つ残るだけ。**ただし「敵ごとの個性」としては採用する** |
| **グーの価値を上げて均す** | 効くが上限がある。上げ切ると `a=b=c` に近づき、非対称ごと消えて手を選ぶ理由がなくなる |

### 進行部分

| 却下した案 | 理由 |
| --- | --- |
| **グリコの距離レース**（節3 案1） | **今の戦闘設計と両立しない。** パーの価値が自分のHPで動く（`c = 4 + 失ったHP`）ことに依存しているため、HPを距離に置き換えるとパーが成立しない |
| **分岐マップ**（節3 案3） | イベント抽選という2つ目の乱数が要り、シナリオテスト3本方針とも衝突する。3日を超える。**将来やりたい**（`docs/01_requirements.md` の「やらないこと」に理由付きで記載） |
| **周回スコアアタック**（節3 案5） | 永続保存と集計が別途要る。3日を超える |
| **移動＋別立て戦闘のハイブリッド**（節3 案4） | 実装量がほぼ2倍。同じじゃんけんが移動中は歩数、戦闘中はダメージという別の意味を持ち、アイデンティティが分裂する |

### 初版から直したもの

| 直した点 | 理由 |
| --- | --- |
| パー = 3ダメージ+4回復 → **4ダメージ+3回復** | 初版はパー勝ちでHP総和が +1 され、**戦闘が終わらない実行列が存在した**（節9.7） |
| にらみの上限なし → **上限2** | k=3 を超えるとあいこ率が上がり1ターン平均が落ちる。終了保証と、加速する性質の維持の両方に要る |

## 影響

- `src/domain/battle.ts` — にらみ・HP・勝敗判定を持つ純粋関数
- `src/data/hands.ts` — グー/チョキ/パーの値（強化で動く）
- `src/data/enemies.ts` — 敵ごとの偏り・耐性・あいこルール
- 乱数は**敵の手決定の1箇所のみ**。`src/lib/rng.ts` 経由
- 戦闘の状態に増えるのは `stare: number` の1フィールドだけ
