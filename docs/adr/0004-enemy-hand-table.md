# ADR 0004: 敵ごとに値表を持たせる

- ステータス: **確定**
- 決定日: 2026-08-11

## 背景

**敵の個性が薄い**というユーザーの指摘から始まった。まず測った。

`scripts/measure.ts` に敵ごとの手の分布を足し（2026-08-11）、
**5体を通した平均との総変動距離**を「隔たり」として出せるようにした。

| 敵 | グー / チョキ / パー | 主な手 | 隔たり |
| --- | --- | --- | --- |
| 1 かかし | 28.4 / 56.5 / 15.2 | チョキ | 12.8% |
| 2 はさみ鳥 | 31.3 / 66.5 / **2.2** | チョキ | 25.8% |
| 3 岩の番人 | 44.0 / 15.5 / 40.5 | **グー** | **28.4%** |
| 4 紙の使者 | **9.4** / 49.3 / 41.3 | チョキ | 18.7% |
| 5 グリコ王 | 27.3 / 21.5 / 51.1 | **パー** | 23.1% |

**戦術的な個性は既に出ていた。** 主な手が3種類に割れ、はさみ鳥ではパーが 2.2%、
紙の使者ではグーが 9.4% と、敵ごとに「使えない手」がはっきりある。
**だから「もっと数値を散らす」は答えではない。**

薄いのは**仕掛けの種類**のほうだった。

- 5体とも **偏り・耐性・HP・本気強化** という同じ4軸の数値違いでできている
- プレイヤーから見えるのは**確率表の数字が動くことだけ**で、
  「この敵は**何か違うことをしてくる**」という手触りがない
- 4体目と5体目は骨格（パー寄り＋チョキ耐性）まで同じ

軸の中で数値をどう振っても、**種類が1つしかないことは埋まらない。**

## 決定

**`EnemyDef` に任意の値表 `hands` を持たせる。省略した敵は `BASE_HANDS` のまま。**

```ts
export interface EnemyDef {
  // …既存のフィールド…
  /** この敵だけの値表。省略すると BASE_HANDS（プレイヤーと同じ値）を使う */
  readonly hands?: HandTable;
}
```

適用は `application` の `enemyHandTable` 1箇所だけで行う。**段を1つ足すだけで、順序は変えない。**

```
1. 敵の値表を選ぶ    enemy.hands ?? BASE_HANDS      ← 足すのはここだけ
2. 弱化を引く        applyHeat(表, enemyHeat, rule)
3. 本気強化を足す    damage + desperateBonus
4. 耐性とにらみ      resolveTurn（敵側の耐性は常に 1）
```

これで作れるようになるもの。**どれも「数値が違う」ではなく「戦い方の前提が違う」。**

| 例 | 値表 | プレイヤーに起きること |
| --- | --- | --- |
| 回復しない敵 | パーの `heal` を 0 | 削り切りの読みが立つ。長期戦が怖くない |
| にらみが凶器になる敵 | グーの `stareBonus` を 6 | **あいこで溜めた にらみが自分に返ってくる。**溜め戦術そのものが賭けになる |
| 大振りな敵 | チョキ 8 / グー 1 | 1発が重いが、外れの手は痛くない。分布を読む価値が跳ね上がる |

## なぜ「まるごと差し替え」にするか

部分上書き（`Partial<Record<Hand, Partial<HandValue>>>`）にしない。

1. **`src/data/` は関数も分岐も書けない**（レイヤチェッカ）。部分上書きは merge が要り、
   その分岐は `application` に増える。**個性を足すたびに `application` が太る形にしない**
2. **9つの数字がその場に全部書いてあるほうが、その敵が何をしてくるか1箇所で読める**
3. 省略できるので、**標準のままの敵はこれまでどおり1行も増えない**

## 守るもの（実装後に必ず確かめる）

| 守るもの | どこが守っているか |
| --- | --- |
| **終了保証** | `resolveTurn` が `heal ≤ dealt − 1` で抑えている（`domain/battle.ts`）。**値表を差し替えても総和は減り続ける。**値表の側で保証しない |
| 値の契約 | `damage` は1以上の整数、`heal` と `stareBonus` は0以上の整数（`docs/03` 節4） |
| **画面に出る数字は必ず実値** | `enemyForecast` は `enemyHandTable` を通っているので、被弾の数字は自動で追随する（`application/game.ts` の唯一の出どころ） |
| 敵は強化されない | 値表は固定。強化されるのはプレイヤーだけ |
| 連打の罰は両陣営に同じ | `applyHeat` は値表の後に掛かる。ルールは共通のまま |

### 画面の変更が**必要**になる（このADRの一部）

**被弾の数字は自動で合うが、`heal` と `stareBonus` は画面に出ていない。**
値表を敵ごとに変えると、**回復量とにらみ倍率が画面から読めないまま変わる。**
これは `docs/03` 節7 の「画面に出る数字は必ず実値」に反する。

したがって、敵パネルの固有能力の行に、**`BASE_HANDS` と違うところだけ**を出す。
既に耐性とあいこルールを自動生成している行（`ui/components/enemyForecast.ts`）に、
値表の差分を足す形にする。**敵ごとに文言を手書きしない。**

> **`EnemyDef.hint` は使わない。** 節3 と節6 は hint を「画面に出す1行」と定義しているが、
> 実装は5体とも一度も表示していない（`grep -rn "hint" src/ui/` が0件）。
> 差分の自動生成のほうが**実値とずれない**ので、hint は落とす。

## ADR 0001 のどこを覆し、どこを維持するか

### 覆すもの: 「敵も同じ値表を使う」と、個性の軸の列挙

ADR 0001 の決定にこう書いてある。

> **ルールは敵にも同じように適用される。** 敵も同じ値表を使い、パーで回復し、
> 共有のにらみがグーに乗る。（略）敵の個性は手の偏り・耐性・HP・あいこルールで出す

**この文の狙いは「ルールの対称性」であって、「数値の同一性」ではない。**
勝ち方の非対称・にらみの共有・パーで回復するという**ルールは全部そのまま維持する。**
覆すのは、**その表に入る数字が5体とも同じでなければならない**という部分だけ。

**新しい証拠が2つある。**

1. **軸の列挙が足りないことが実測で分かった。** ADR 0001 は「偏り・耐性・HP・あいこルール」で
   足りるという見込みで書かれていた。上の計測は、その4軸では**仕掛けの種類が1つにしかならない**
   ことを示している
2. **「同じ値表だからプレイヤーが敵を読める」という前提が、もう成り立っていない。**
   2026-08-10 に敵パネルへ**3手ぶんの被弾の実値**を出した（`docs/03` 節7）。
   プレイヤーは今、`BASE_HANDS` から推測していない。**画面の数字を読んでいる。**
   値表が違っても読めなくならない

### 覆さないもの

- ADR 0001 の戦闘方式（グー/チョキ/パー・にらみ・上限2・あいこダメージ・決着で0）
- **にらみは両者で共有する**（敵の `stareBonus` を上げるのは、この帰結を使うのであって破らない）
- **敵もパーで回復する**（回復量を0にする敵は作れるが、仕組みは残す）
- **強化されるのはプレイヤーだけ**
- 後出しの禁止、**敵に履歴学習AIを作らない**、乱数は敵の手決定の1箇所のみ
- ADR 0003 の連打の罰（**両陣営に同じルール**を維持）

## 却下した案

| 却下した案 | 理由 |
| --- | --- |
| **部分上書き** | `src/data/` に分岐が書けず、merge が `application` に乗る。上の「なぜまるごとか」 |
| **敵ごとの連打ルール（`HeatRule`）** | ADR 0003 の「ルールは敵にも同じように適用する」を覆すことになる。値表で足りる |
| **敵ごとのにらみ上限** | ADR 0001 が「上限2は全敵共通、変えない」と明記。覆さない |
| **敵に2つ目の行動を持たせる** | 「行動はじゃんけん1回だけ」（ADR 0001）を壊す |
| **`hint` に手書きで説明を書く** | 実値とずれる。ずれた実績がある（`docs/03` 節4 の `dealtDamage` の経緯） |
| **あいこルールに「急かす敵」を足す**（⑤） | 今回は見送り。にらみが溜まらないと**あいこが永久に無害になり、終了保証が壊れる**（`docs/03` 不変条件8がにらみ上限到達に依存）。入れるなら「あいこで必ず双方1ダメージ」とセットで、別のADRで |

## 影響

| ファイル | 変わるもの |
| --- | --- |
| `src/domain/enemy.ts` | `EnemyDef` に `hands?: HandTable`（`hint` は落とす） |
| `src/application/game.ts` | `enemyHandTable` の1行（`enemy.hands ?? BASE_HANDS`） |
| `src/data/enemies.ts` | 差をつけたい敵にだけ値表を書く |
| `src/ui/components/enemyForecast.ts` | 固有能力の行に、`BASE_HANDS` との差分を出す |
| `docs/01_requirements.md` | 「敵もプレイヤーと同じ値表を使う」を書き換える |
| `docs/03_detailed-design.md` | 節3（`EnemyDef`）・節5（`enemyHandTable`）・節6・節7 |

**`src/domain/battle.ts` は変更しない。** 触る必要が出たら設計が間違っている。

### どの敵にどう振るかは、このADRでは決めない

**5体の値をどうするかは `/balance` の仕事。** ここで決めるのは仕組みだけ。
判断は `scripts/measure.ts` の「敵ごとの手の分布」の**隔たりが散ること**と、
突破率のカーブ（`docs/03` 節6）が崩れないことの両方で行う。
