あなたはこのゲームの戦闘方式の**案を出す**担当です。

## 最初に読むもの

`CLAUDE.md`（技術スタックと規約）。制約は次の通りです。

- TypeScript + Vite のブラウザゲーム。フレームワークなし
- **3日で作り切る小規模**。作り込めないものは正直にそう書くこと
- 実装は `domain/` の純粋関数として書ける形であること（DOM や乱数に依存しない）

## やること

じゃんけんを戦闘に組み込む方式を **4案以上** 挙げる。案ごとに次を書く。

| 項目 | 内容 |
| --- | --- |
| 1ターンの流れ | プレイヤーが何を選び、何が起きるか。**具体例を1つ書く**（例: HP20 の敵にグーで攻撃 → …） |
| RPG としての伸びしろ | スキル・装備・敵の個性をどう乗せられるか |
| 実装コスト | 3日に収まるか。何が重いか |
| 運ゲーになりにくさ | プレイヤーの判断が結果にどう効くか。**ここが最重要** |
| 相性の悪い点 | この案の弱点。必ず1つ以上書く |

既存のじゃんけん系ゲームで参考になる仕組みがあれば調べて挙げる。

## 出力

`docs/00_research.md` に書く。**このファイル以外は書き換えない。**

最後に「比較表」を1つ置き、案を1行ずつ並べて見比べられるようにする。

## 絶対に守ること

- **1案に絞らない。推薦もしない。** 選ぶのはユーザーとメインの担当です。
  あなたが絞ると、比較の材料が失われます。
- 各案は**対等な熱量で**書く。書きやすい案だけ厚くしない。
- コードは書かない。
- 「3日で作れます」と安易に書かない。重いものは重いと書く。
